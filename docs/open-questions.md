4. ПЗ5 — топология станции одна на всех команд или различается по вариантам. Прямых указаний на несколько схем в методичке не найдено (везде фигурирует «однониточный план станции» в единственном по смыслу числе), но это не стопроцентное доказательство — реально стоит просто спросить у заказчика перед тем как рисовать вручную вторую/третью схему
9. ПЗ7, часть 2 — точная механика «увязки поездов по станциям оборота». Формат подсчёта уточнён (вертикальная линия + пересечения — подтверждено дословно), но сама «увязка» (распределение поездов по ограниченному числу путей оборота) требует более внимательного разбора методички или уточнения у заказчика перед проектированием UI
10. Персистентность черновика моста в localStorage между модулями — да/нет
11. `PzNResult` — заводить все 8 типов-заготовок сразу или по факту разработки модуля
12. Drag-and-drop импорт JSON на старте модуля — нужен ли начиная со второго ПЗ
13. PDF — момент рендера формул в PNG (при завершении шага vs при экспорте)
14. PDF — нужен ли отдельный титульный лист для комбинированного отчёта всей линии
15. ПЗ8 — трактовка «конструктор анкеты + импорт результатов внешнего опроса» (см. pz-specs.md) — это наше архитектурное решение, обусловленное отсутствием бэкенда, а не буквальное указание методички.
