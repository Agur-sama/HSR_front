- Наполняемость автомобиля: `B14=1,3` чел.

## ✅ ГЛАВНАЯ ФОРМУЛА — подтверждена трассировкой по ячейкам, готова для MVP



```ts
// Все проценты — из варианта (pz1-variants.md), кроме grpCurrent/popCurrent — ручной ввод (Росстат)
function forecastTotalDemand(input: {
  existingAnnualFlow: number;      // F_существ.рынка (сумма по всем видам транспорта, из шага 2)
  grpCurrent1: number; grpCurrent2: number;   // ручной ввод, Росстат
  popCurrent1: number; popCurrent2: number;   // ручной ввод, Росстат
  grpGrowthPct1: number; grpGrowthPct2: number; // из варианта
  popGrowthPct1: number; popGrowthPct2: number; // из варианта
  kGdpFlow1: number; kGdpFlow2: number;         // из варианта
  inducedDemandPct: number;                     // из варианта
}): { baseForecase: number; inducedDemand: number; totalForecast: number } {
  const grpFuture1 = input.grpCurrent1 * (1 + input.grpGrowthPct1);
  const grpFuture2 = input.grpCurrent2 * (1 + input.grpGrowthPct2);
  const popFuture1 = input.popCurrent1 * (1 + input.popGrowthPct1);
  const popFuture2 = input.popCurrent2 * (1 + input.popGrowthPct2);

  const grpDelta = (grpFuture1 + grpFuture2) / (input.grpCurrent1 + input.grpCurrent2);
  const popDelta = (popFuture1 + popFuture2) / (input.popCurrent1 + input.popCurrent2);
  const kWeighted =
    (input.popCurrent1 * input.kGdpFlow1 + input.popCurrent2 * input.kGdpFlow2) /
    (input.popCurrent1 + input.popCurrent2);

  const baseForecase = input.existingAnnualFlow * grpDelta * kWeighted * popDelta;
  const inducedDemand = baseForecase * input.inducedDemandPct;

  return { baseForecase, inducedDemand, totalForecast: baseForecase + inducedDemand };
}
```

**Проверено на реальном примере из файла:** existingAnnualFlow=2 325 272,4, grpDelta=1,1553, kWeighted=0,8223, popDelta=1, inducedDemandPct=0,35 → `baseForecase=2 208 992,6`, `inducedDemand=773 147,4`, `totalForecast=2 982 140,0` — совпадает с ячейкой `Параметры!D4` день-в-день.

**Это формула ОБЩЕГО роста рынка перевозок (все виды транспорта суммарно), не доли именно ВСМ.** Распределение прогноза между видами транспорта — отдельная модель (гравитационное распределение + пороги эластичности цены/времени). **Устарело как открытый вопрос:** ниже по этому файлу (раздел «Распределение по видам транспорта») эта модель полностью дотрассирована и не является упрощением/допущением — не путать с текущим состоянием.

**Ручной ввод, которого не было явно выделено раньше:** текущие ВРП и население двух регионов (Росстат) — 4 числовых поля. Методичка ожидает, что их вносит студент, не мы (данные не зашиты в вариант).

Изначальная оценка «модальный сплит с монетизацией времени» была верной, но неполной. Прямой разбор ~150 формул с трёх листов показал ещё два самостоятельных подмодуля, которых не было в первом описании:

1. **Модель индуцированного спроса с ценовыми порогами** (`Параметры!E112`, `F112`) — вложенные условия, проверяющие попадание цены/времени в диапазон относительно конкурирующих видов транспорта, с линейной интерполяцией коэффициента между границами диапазона. Это отдельная модель эластичности спроса, не часть модального сплита.
2. **Взвешенное распределение потока через кубическую функцию** (`Параметры!N134: =((N139+N140)*24*N40)^3`, далее нормализуется серией делений на суммы, строки 134–146) — по структуре похоже на гравитационную модель распределения (аналог модели Хаффа/гравитационной модели транспортных потоков), не на пропорциональное деление.

Порядка 150 формул, плотные перекрёстные ссылки между листами `Параметры` ↔ `Виды транспорта` ↔ `Пассажиропотоки`, много абсолютных ссылок и агрегирующих функций (`MIN`, `MEDIAN`, `SUM`) по диапазонам без явных подписей смысла.

**Вывод (историческая заметка — на момент первого разбора, до полной трассировки ниже):** это не рядовая расчётная функция уровня ПЗ4/ПЗ6, реверс-инжиниринг занял отдельный разбор. Оригинальный `.xlsx` держать как живой референс — часть смысла (например, что именно означает кубическая нормализация в N134) не считывается только из формул. **Этот вывод больше не про статус «можно отложить»** — см. следующий раздел, модель дотрассирована и реализуема полностью.

Если студент исключил вид транспорта из корреспонденции, в модель он всё равно подаётся — строкой с нулями и флагом `excluded`. Все три слагаемых захвата у него нулевые, вес в нормализации нулевой, строка в результате сохраняется.

**Не перераспределять его долю между оставшимися видами** — это отменённое допущение. Разница принципиальная: если исключённый вид просто убрать из массива входов, оставшиеся перенормируются между собой и получат его долю, чего заказчик явно не хочет.

### Формула распределения (три слагаемых на каждый вид транспорта)

```
Прогноз_вид = Захват_прямой + Захват_гравитационный + Захват_индуцированный

Захват_прямой = F_существ_рынка × (доля_вида_существ × (1 − штраф_вида))
  доля_вида_существ = поток_вида_существ / F_существ_рынка
  штраф_вида = MAX(вес_время, вес_цена, вес_комфорт) этого вида   ← нашли в строках 120–122

Захват_гравитационный = Остаток × Вес_гравитационный_вида
  Остаток = F_существ_рынка − Σ(Захват_прямой по всем видам)
  Вес_гравитационный_вида — считается через цепочку:
    1. Импеданс = ((время_в_пути + время_ожидания) × 24 × TTC_вида) ^ 3
    2. доля_импеданса = Импеданс_вида / Σ(Импеданс)
    3. привлекательность = 1 / доля_импеданса
    4. Вес_гравитационный = привлекательность_вида / Σ(привлекательность)
    (меньше импеданс = больше вес — модель "чем быстрее и дешевле, тем привлекательнее")

Захват_индуцированный = F_индуц × (экономия_времени_вида / Σ(экономия_времени))
  экономия_времени_вида = существующее_время_в_пути − время_в_пути_на_ВСМ
```

## Структура (укрупнённо, как было — верно на уровне листов и итоговых значений)


1. **Стоимость суммарная на 1 чел** по каждому виду = стоимость проезда по городу 1 + NCT + стоимость проезда по городу 2 (`E = SUM(B:D)`). Для авто — своя формула через бензин/ОСАГО/расход.
2. **Стоимость за 1 км** = суммарная / расстояние.
3. **Стоимость времени в пути** `C_time = время × коэфф_комфорта × (1/частота) × (ЗП_год / рабочие_часы)` — то есть время монетизируется через зарплату.
4. **Совокупные транспортные затраты TTC** = стоимость проезда + стоимость времени.
5. **Коэффициенты K_ttc, K_comf** — нормировка каждого вида относительно минимума по столбцу (`E/MIN(E)`).
6. **Модальный сплит** — распределение суммарного потока по видам транспорта на основе TTC (медианные/взвешенные агрегаты `TTC_base`, `TTC_model`).

## Прирост потока (лист «Параметры»)
```
F_forecast = F_current × GRP_delta × k_gdp-flow × Pop_delta

GRP_delta = (GRP_future1 + GRP_future2) / (GRP_current1 + GRP_current2)
Pop_delta = (Pop_future1 + Pop_future2) / (Pop_current1 + Pop_current2)
```
`GRP_future`, `Pop_future`, `k_gdp-flow` — из вариантной таблицы (см. pz1-variants.md).

## Важно для кодирования
- Это самый сложный расчётный шаг во всём ПЗ1 (модальный сплит, монетизация времени, логит-подобное распределение). При переносе в `shared/lib` разбить на отдельные чистые функции по каждому блоку (стоимость, время, TTC, сплит, прирост), каждую с тестом на значениях выше.
- Значения выше — готовая интеграционная фикстура: подать вход 500 км + константы примера → ожидать итог 9940,47 пасс./сутки прогноз (с разумной погрешностью, т.к. в Excel много промежуточных округлений). **Статус модели — не заглушка, реализуется полностью** (см. предупреждение в начале файла и раздел «Распределение по видам транспорта»); формулировки про MVP-заглушку в этом разделе — историческая заметка первого прохода по файлу, датируемая до полной трассировки, оставлена только чтобы показать, как менялась оценка сложности.
- В архиве есть также `Без_пригорода_Прогнозирование_пасс_потока_v2.xlsx` — вариант модели без пригородного сообщения (вероятно для направлений, где его нет). Учесть при кодировании как параметр модели, не отдельную копию.
