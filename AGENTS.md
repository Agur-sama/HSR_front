# vsm-simulator.ru — архитектура проекта

Веб-симулятор ВСМ — 8 интерактивных модулей практических заданий (ПЗ1–ПЗ8), встраиваемых в курсы iSpring Suite как Web Object через `<iframe>`. Аудитория — студенты Школы ВСМ (ДПИШ, РУТ МИИТ), команды 5–6 человек, работают очно на парах с одного экрана. Репозиторий `HSR_front`, ветка `wth`.

Стек: React 19 + TypeScript + Vite, Vitest. Без бэкенда — преподаватель проверяет вручную по PDF, аккаунты и роли не нужны.

## Самые частые срывы на этом проекте — коротко

- Не предлагать бэкенд/БД/авторизацию/роли — их нет и не будет
- Не хранить формулы в JSX — только в `shared/lib`, с тестом
- Не использовать `any`
- Не импортировать код одного ПЗ в другой напрямую
- Не добавлять глобальный state-manager (Redux/Zustand/XState) — состояние модуля живёт в React Context, подробности в `docs/architecture.md`

Полный список запретов и обоснований — в `docs/architecture.md`.

## Правила вывода кода

- Изолированные переиспользуемые React-компоненты на TS, строгая типизация через `interface`/`type`
- Не переписывать файлы целиком без явной команды — точечные правки
- Перед объёмной новой логикой — сначала план (файлы, интерфейсы), не сразу код
- Каждая расчётная функция — с тестом на примере из методички (`docs/examples/pzN.md`)
- Не хватает данных из методички — прямо сказать, не придумывать числа
- Дублировать интерфейсы в Artifacts/визуализации для проверки интерактива и адаптивности перед кодированием
