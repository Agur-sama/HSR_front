# vsm-simulator.ru

Веб-симулятор ВСМ — интерактивные модули практических заданий для курсов Школы ВСМ (ДПИШ, РУТ МИИТ). Модули встраиваются в курс iSpring Suite как Web Object через `<iframe>`.

Сейчас в сборке два модуля: **ПЗ1** (технико-экономическое обоснование проекта ВСМ) и **ПЗ2** (календарно-сетевой график).

## Требования

- Node.js **20.19+ или 22.12+** (требование Vite 7; версии 20.0–20.18 и вся ветка 21 не подойдут)
- npm 10 или новее

Других зависимостей нет: **у проекта нет бэкенда, базы данных и авторизации.** Это статическое приложение, преподаватель проверяет работы вручную по PDF, который студент скачивает сам.

## Сборка с нуля

```bash
git clone https://github.com/Agur-sama/HSR_front.git
cd HSR_front
npm install
npm run build
```

Результат — папка `dist/`. Она в `.gitignore` и пересобирается из исходников, в репозитории её быть не должно.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер Vite с горячей перезагрузкой |
| `npm run build` | Проверка типов (`tsc -b`) и продакшен-сборка в `dist/` |
| `npm run preview` | Локальный просмотр собранного `dist/` |
| `npm test` | Прогон тестов Vitest |

Перед коммитом должны проходить и `npm test`, и `npm run build` — последний включает проверку типов.

## Как открыть модуль

Модуль выбирается параметром `?pz=` в адресе:

- `http://localhost:5173/?pz=1` — ПЗ1
- `http://localhost:5173/?pz=2` — ПЗ2

Без параметра или с номером незаведённого модуля открывается экран «Модуль не найден» со списком доступных.

## Деплой

Статическая раздача содержимого `dist/` любым веб-сервером — Caddy, Nginx. Ничего собирать на сервере не нужно, никаких переменных окружения приложение не читает.

Приложение обслуживает один HTML на все адреса, поэтому сервер должен отдавать `index.html` на любой путь (SPA-fallback). Пример для Caddy:

```
vsm-simulator.ru {
    root * /var/www/vsm-simulator/dist
    try_files {path} /index.html
    file_server
}
```

### Встраивание в iSpring

Web Object в iSpring — прямоугольная область фиксированного размера, автор курса растягивает её вручную. Приложение не управляет размером контейнера программно. Ориентир по минимальному размеру — 16:9 от примерно 960×540; при более тесных пропорциях вёрстка деградирует, а не ломается.

Карта ПЗ1 обращается к двум сервисам OpenStreetMap: тайлы подложки и определение региона станции по координатам. Поэтому на машине студента нужен доступ в интернет. Без него карта останется пустой, а регион придётся выбрать вручную из списка — остальные шаги продолжат работать. Подробности и ограничения — в [`docs/architecture.md`](./docs/architecture.md), раздел «Внешние сервисы времени выполнения».

## Структура

```
src/
  app/        — корневая оболочка, выбор модуля по ?pz=
  modules/    — код модулей: pz1/, pz2/
  shared/     — переиспользуемые компоненты (ui/) и чистые расчётные функции (lib/)
  bridge/     — JSON-мост: схема, чтение и запись, React-контекст состояния модуля
  pdf/        — генерация PDF-отчёта
docs/         — архитектура, дизайн-система, спецификации ПЗ, открытые вопросы
```

Расчётные формулы живут только в `src/shared/lib`, каждая с тестом рядом. В компонентах формул быть не должно.

## Данные студента

Состояние работы хранится **только в JSON-файле**, который студент скачивает кнопкой «Сохранить» на любом шаге и загружает обратно на интро модуля. Ни localStorage, ни сервера. Один и тот же файл накапливает результаты всех ПЗ и предзаполняет входы следующих — но каждый модуль обязан работать и с чистого листа.
