# TASK.md — сборка MVP (ПЗ1) к понедельнику

Прочитай сначала: `AGENTS.md` → `docs/architecture.md` → `docs/design-system.md` (+ открой `docs/design-reference.html`) → `docs/pz-specs.md` (раздел ПЗ1) → `docs/pz1-copy-and-validation.md` (все тексты интерфейса и правила валидации — используй буквально, не переписывай) → `docs/pdf-report.md` (макет PDF-отчёта) → `docs/open-questions.md`. Этот файл — план сборки, он НЕ заменяет их, а ссылается на них. При конфликте инструкций приоритет у `docs/architecture.md`.

## Цель

Работающий MVP модуля ПЗ1, встраиваемый как Web Object (`?pz=1`). Дедлайн — понедельник. Приоритет — чтобы к понедельнику было **что показать**, даже если самый тяжёлый шаг (карта) не успеет полностью. Поэтому порядок сборки — от каркаса к карте, а не наоборот.

## Жёсткие правила (из architecture.md, повтор для фокуса)

- Без бэкенда/БД/авторизации/роутинга на сервере. Одна статическая сборка `vite build`.
- Формулы и бизнес-логика — только в `shared/lib`, с тестом. Никогда в JSX.
- Никакого `any`. Никакого глобального state-manager — состояние модуля в React Context.
- Код одного ПЗ не импортирует другой ПЗ.
- Цвета только `#3a288b` (indigo) и `#08a696` (teal), шрифт Raleway. Вектор «магистраль/табло» — см. design-system.md.
- Не хватает данных из методички — оставь `// TODO: уточнить` и напиши об этом, не выдумывай числа.
- Открытые вопросы из `docs/open-questions.md` — не решай молча.

## Точка входа и роутинг

- Один билд, 8 точек входа через URL-параметр `?pz=N`. Для MVP реализуй только `pz=1`, но заложи обработку параметра так, чтобы `pz=2..8` можно было добавить позже без переписывания входа.
- `app/` читает `?pz=` из `window.location.search`, выбирает модуль из реестра `modules/registry.ts` (маппинг номер → компонент модуля), рендерит его. Неизвестный/отсутствующий `pz` → заглушка «модуль не найден», не краш.
- Корень — `h-screen`, `overflow-hidden`. Внутренние области скроллятся изолированно. См. ограничения iSpring в architecture.md.

## Порядок сборки (строго по шагам — каждый шаг должен компилироваться и запускаться)

### Шаг 0 — каркас проекта
- Vite + React 19 + TS, Vitest. Структура папок ровно как в `docs/architecture.md` (раздел «Структура репозитория»).
- `styles.css` с CSS-переменными: `--indigo: #3a288b; --teal: #08a696;` + подключение Raleway через Google Fonts.
- Пустой прогоняемый тест, чтобы убедиться что Vitest работает.

### Шаг 1 — типы моста и состояние
- `bridge/schema.ts` — `Passport`, `BridgeSchema`, `Pz1Result` (структура ниже). Остальные `PzNResult` пока `type PzNResult = unknown` с TODO — не заводи все 8 сразу (см. open-questions №11).
- `bridge/io.ts` — экспорт `BridgeSchema` в JSON-файл (скачивание) и импорт (парсинг + валидация `schemaVersion`). Тесты на парсинг и на битый JSON.
- `bridge/context.tsx` — `ModuleStateProvider`, хранит состояние модуля (текущая фаза, текущий шаг, накопленные данные). Инициализация из импортированного моста, если есть.

```ts
interface Pz1Result {
  // Станции — ЛИМИТ: ровно 2 terminal (А,Г) + максимум 2 intermediate (Б,В). Всего 2..4.
  stations: Array<{ label: 'А'|'Б'|'В'|'Г'; name: string; lat: number; lng: number; type: 'terminal'|'intermediate' }>;
  // Вершины линии трассы — БЕЗ ЛИМИТА (0..∞). Студент ставит сколько нужно, чтобы обходить
  // воду/горы. Это САМОСТОЯТЕЛЬНЫЙ массив, НЕ derived из stations. Порядок [lng, lat].
  // Соединять станции прямыми = баг. Линия рисуется polyline по этим вершинам.
  routeLine: Array<[number, number]>;
  // остальные поля (пасспоток, 13 показателей) добавляй по мере шагов 5+, не сразу
}
```

### Шаг 2 — оболочка модуля (переиспользуемая, `shared/ui`)
Это самое ценное на будущее — делай аккуратно, это переиспользуют все 8 ПЗ.
- `shared/ui/ModuleShell` — обёртка с жизненным циклом: интро → теория → задание → итог. Принимает конфиг шагов.
- `shared/ui/ProgressRoute` — прогресс-трасса (горизонтальная линия-рельс со станциями-этапами). Дизайн — см. design-system.md, вектор «магистраль/табло». Пройденный участок — заливка teal, текущая станция крупнее с halo.
- `shared/ui/StepHeader` — шапка с крупным моноширинным номером шага (`03 из 05`), teal-callout «Цель практического задания».
Провизуальный образец этих компонентов уже согласован в чате-проектировании — придерживайся его.

### Шаг 3 — интро ПЗ1
- Экран паспорта: команда (текст), название линии (текст), селектор варианта направления (6 вариантов — см. `modules/pz1/variants.ts`, заполни из методички ПЗ1; если точных 6 направлений нет под рукой — TODO и заглушка на 2-3 примерных, помеченных как需уточнения).
- Опциональная кнопка «Загрузить данные (JSON)» — drag-drop, необязательная. Работы персональные, не командные (см. ниже «важно про данные»).

### Шаг 4 — простые шаги задания ПЗ1 (без карты)
Собери сначала НЕ-картовые шаги, чтобы MVP жил даже без MapLibre:
- `data-entry` таблицы потребительских свойств (шаг 2 спеки ПЗ1) — переиспользуемый `shared/ui/DataEntryTable`.
- `data-entry-hint` для итоговых показателей (шаг 5 спеки) — переиспользуемый `shared/ui/FieldWithHint` (label + input + постоянно видимая справочная подсказка рядом, НЕ placeholder). Согласованный образец — в чате.

### Шаг 5 — экран «Итог» + PDF (минимальный)
- Сводка введённого + кнопка «Скачать PDF».
- PDF для MVP — минимальный: титул (линия, команда, вариант, дата) + текстовая сводка шагов. Формулы-в-картинку и превью карты — можно отложить (TODO), если не успеваешь. Главное чтобы кнопка работала и отдавала валидный PDF.
- Экспорт JSON моста тут же.

### Шаг 6 — КАРТА (делать последней, это риск дедлайна)
- `maplibre-gl`, топографический стиль с `name:ru`. Для MVP допустимо взять хостовый провайдер (MapTiler Outdoor/Topo) на временный ключ — PMTiles-самохостинг это продакшен-фаза, НЕ для MVP.
- 2D-подложка, БЕЗ 3D/pitch/DEM. Просто топокарта сверху.
- Датасет городов РФ — для MVP хватит сокращённого (20-30 крупнейших городов на выбранном направлении), полный ~200 — потом. Поиск по русскому названию.
- Интерактив — ДВА раздельных режима (как «метка» и «линия» в Яндекс.Картах):
  - режим «Станция»: клик ставит станцию, drag двигает. Тип `terminal` (А/Г) / `intermediate` (Б/В). ЛИМИТ: 2 терминальные + максимум 2 промежуточные. При попытке поставить 3-ю промежуточную — блокировать и показать подсказку.
  - режим «Линия трассы»: клик добавляет вершину в конец линии, drag двигает вершину, вставка вершины между двумя существующими, удаление вершины. Вершин СКОЛЬКО УГОДНО — студент обводит воду/горы.
- **НЕ строить линию автоматически по станциям прямыми отрезками** — это была ошибка предыдущей версии. `routeLine` — независимый массив вершин, редактируется отдельно от станций.
- Результат: `Pz1Result.stations` (лимитированные метки) + `Pz1Result.routeLine` (неограниченные вершины), два раздельных массива.
- **Если карта не успевает к понедельнику:** оставь шаг-заглушку «карта в разработке» с возможностью ручного ввода станций (координаты/названия текстом), чтобы модуль был проходим целиком. Это приемлемая деградация MVP.

## Важно про данные (изменилось — учти)

Работы студентов **персональные**, не командные. Команда существует «на словах», препод проверяет работы рядом. Поэтому:
- Паспорт хранит `team` только для группировки, данные не общие.
- JSON-мост — удобство «если файл сохранился», НЕ обязательный поток. Каждый ПЗ обязан открываться с чистого листа (ручной ввод/вариант).
- Между сессиями (ПЗ разнесены на месяцы, возможно разные компьютеры) состояние ненадёжно. Для MVP: показывай студенту заметное напоминание на экране «Итог» — «Сохраните файл перед выходом, иначе прогресс не восстановится». Персистентность в localStorage — открытый вопрос №10, для MVP НЕ реализуй, только предупреждение.

## Definition of Done для MVP

- [ ] `?pz=1` открывается как отдельная страница, не крашится на других `pz`
- [ ] Проходится весь цикл: интро → теория → задание → итог
- [ ] Хотя бы data-entry и data-entry-hint шаги полностью рабочие
- [ ] Карта: либо рабочая (клик/drag станций, лимит 2 промежуточных), либо честная заглушка с ручным вводом
- [ ] Кнопка «Скачать PDF» отдаёт валидный файл
- [ ] Экспорт/импорт JSON моста работает
- [ ] `vite build` проходит, собранная статика запускается
- [ ] Все расчётные функции (если появятся на шаге 5) покрыты тестом из `docs/examples/`
- [ ] Ни одного `any`, формулы не в JSX, оболочка переиспользуема

## Если не успеваешь

Режь в таком порядке (сохраняя проходимость модуля): полный датасет городов → карта целиком (заглушка вместо неё) → PDF-формулы-в-картинку → часть data-entry таблиц. НЕ режь: каркас, оболочку `shared/ui`, типы моста — это фундамент для остальных 7 ПЗ, на нём нельзя экономить.
