# vsm-simulator.ru — правила работы над проектом

Веб-симулятор ВСМ — 8 интерактивных модулей практических заданий (ПЗ1–ПЗ8), встраиваемых в курсы iSpring Suite как Web Object через `<iframe>`. Аудитория — студенты Школы ВСМ (ДПИШ, РУТ МИИТ), команды 5–6 человек, работают очно на парах с одного экрана.

Стек: React 19 + TypeScript + Vite, Vitest. Без бэкенда — преподаватель проверяет вручную по PDF, аккаунты и роли не нужны.

Как поднять проект и что нужно из окружения — в [`README.md`](./README.md).

## Ограничения, которые нарушают чаще всего

- Не предлагать бэкенд/БД/авторизацию/роли — их нет и не будет
- Не хранить формулы в JSX — только в `shared/lib`, с тестом
- Не использовать `any`
- Не импортировать код одного ПЗ в другой напрямую
- Не добавлять глобальный state-manager (Redux/Zustand/XState) — состояние модуля живёт в React Context, подробности в `docs/architecture.md`

Полный список запретов и обоснований — в `docs/architecture.md`.

## Правила работы с кодом

- Изолированные переиспользуемые React-компоненты на TS, строгая типизация через `interface`/`type`
- Точечные правки вместо переписывания файлов целиком
- Перед объёмной новой логикой — сначала план (файлы, интерфейсы), потом код
- Каждая расчётная функция — с тестом на примере из методички (`docs/examples/`)
- Не хватает данных из методички — сказать об этом прямо, а не подставлять правдоподобные числа
- Перед вёрсткой нового экрана — сверяться с `docs/design-reference.html`, а не подбирать цвета и размеры на глаз
